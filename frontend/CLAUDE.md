# CLAUDE.md — `frontend/`

Guidance specific to the bundled GUI's React SPA. See the root `CLAUDE.md` for project-wide invariants and the cross-cutting features this SPA plugs into (Live GUI push updates, GUI pause toggle, Runtime-configurable log level, etc.) — this file only covers `frontend/`-internal structure.

A React + Vite + Tailwind SPA (TypeScript) served by the FastAPI backend (`src/ynab_auto_sync/webapp/`). Five tabs, no router (local state only — sits behind an external reverse proxy with its own auth, no deep-linking need):

- `contexts/SyncStatusContext.tsx` (`SyncStatusProvider`, wraps `<main>` in `App.tsx` — ABOVE the tab switch, not inside `Dashboard.tsx`, because `App.tsx` fully mounts/unmounts each page on tab click and a connection owned inside `Dashboard.tsx` would reconnect on every tab click; owns the `/api/ws` connection, reconnect-with-backoff, and the 15s-poll fallback — see root CLAUDE.md's "Live GUI push updates") exposes `useSyncStatus()` (`status`/`progress`/`connectionState`/`error`) to `Dashboard.tsx` (its "Last run" stat tiles include `fetched_last_run` alongside imported/updated/duplicates/resolved-deleted — the raw pre-dedup count, placed first since it's upstream of the others; a "Sync now" button calls `POST /api/sync-now` — the button's own loading/"requested" state is still local optimistic UI, but `status`/`progress` themselves are now push-driven, not polled, whenever the websocket is up; next to it, a "Pause syncing"/"Resume syncing" button calls `POST /api/pause` (`api/client.ts`'s `setPaused()`) — reads `run_metadata.paused` directly off the shared status object rather than tracking its own mirrored boolean, so it stays correct across MQTT-triggered pauses and other GUI clients too, only local state is the in-flight/error UI (mirrors `handleLogLevelChange`'s try/catch/finally shape, not optimistic-update-then-revert since there's no local value to revert); a "Log level" `<select>` fetches `GET /api/settings` on mount and `PATCH`es on change, optimistic-update-then-revert-on-failure — see root CLAUDE.md's "Runtime-configurable log level").
- `Mappings.tsx` (drag a provider account onto a YNAB account to create a mapping — native HTML5 drag-and-drop, no library, with a `<select>` fallback so dragging is never the only path; warns before remapping/unmapping an account with `tracked_count > 0`, since YNAB permanently reserves the already-used import ids and that history will NOT re-import elsewhere; each YNAB account drop target shows a "N linked" badge — a pure client-side count of `mappings` filtered by `ynab_account_id`, no new endpoint needed since YNAB account ids are globally unique UUIDs; a "Clear all" button on the existing-mappings table calls the bulk `DELETE /api/mappings`, gated behind the same confirmation-modal pattern as remap/unmap, reporting the combined `tracked_count` across every mapping about to be cleared; the existing-mappings table's `display_name` cell is click-to-edit (`renamingId`/`renameValue` state, `doRename` → `updateMapping(id, {display_name})`) — needed because the provider-side friendly-naming fix in `provider.py::list_accounts()` only affects a mapping's `display_name` at the moment it's first created, never retroactively, so this is the fix path for anything mapped before that landed; the explicit "Refresh" button's `loadAll(true)` passes `forceRefresh: true` through BOTH `listProviders()` and `listYnabAccounts()` (`loadBudgets(forceRefresh)`) so that one action bypasses both `SpareBank1Provider`'s account-list TTL cache AND `YnabAccountsCache`'s, while the normal per-tab-mount fetch (`loadAll()`, no argument) leaves both cached).
- `DeletedTransactions.tsx` (lists + re-adds deleted-transaction candidates).
- `Import.tsx` (two-phase stateless upload: POST the same file with `dry_run=true` for a preview, then again with `dry_run=false` to commit).
- `AuditLog.tsx` (one-shot fetch on mount + manual "Refresh" — deliberately NOT websocket-driven like `SyncStatusContext`, since that context is purpose-built for current run-state, not a historical event list; a "Skipped: Hidden"/"Skipped: Shown" pill toggle, default off, is the one required-off-by-default control; category filter pills plus a `StatTile`-style summary strip sourced from the response's `counts`, always visible even with skipped hidden, as a nudge that skipped rows exist; an "Account" column + `<select>` filter, sourced from `GET /api/status`'s existing `accounts` list rather than a new endpoint — mirrors `Import.tsx`'s account-override dropdown pattern, and resolves a raw `account_key` to its configured `display_name` for both the filter options and the table cell; every sortable column header (`COLUMNS`' `sortKey`) is clickable, toggling `asc`/`desc` on repeat clicks of the same column and defaulting to `desc` for Time / `asc` for everything else on a fresh column, with a ▲/▼ indicator — sorting is server-side (`sort_by`/`sort_dir` query params), not client-side, since pagination means only one page is ever in memory; "Load more" pagination via `offset`, not page-number controls).

`src/api/client.ts` holds the typed fetch wrappers; all calls are relative paths since production serves the built static files from the same FastAPI app.

Built with `npm install && npm run build` in `frontend/` (Node 24/npm 11 confirmed working); needs `@types/react`/`@types/react-dom` as devDependencies beyond the originally-specified minimal set — TypeScript's JSX checking requires them, not optional. **Editing frontend source has zero effect until it's rebuilt** — same "no hot reload" gotcha as the Python side, but via a separate build step, not just a process restart (see root CLAUDE.md's Operational gotchas).
