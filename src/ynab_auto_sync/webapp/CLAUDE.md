# CLAUDE.md — `src/ynab_auto_sync/webapp/`

Guidance specific to the FastAPI backend for the bundled GUI. See the root `CLAUDE.md` for project-wide invariants, the `notifications/`/`alerts/` seams, and cross-cutting features this package's routes plug into (Live GUI push updates, GUI pause toggle, Runtime-configurable log level, etc.) — this file only covers `webapp/`-internal structure.

- `app.py`'s `create_app(config, engine, db, providers_map=None, scheduler=None, ws_manager=None)` wires nine `/api/*` routers plus a `StaticFiles` mount (for the built `frontend/dist`, mounted *last* so it only catches what the API routers don't) onto `app.state`. `providers_map`/`scheduler`/`ws_manager` are optional kwargs (default `{}`/`None`/`None` on `app.state`) so pre-existing callers/tests that only pass `(config, engine, db)` keep working; `deps.py`'s `get_providers`/`get_scheduler`/`get_ws_manager` hand them to routes in the same style as the original three getters (`get_config`/`get_engine`/`get_db`) — **except `routes/ws.py`, which can't use those `Depends(...)`-based getters at all**: they're typed for an HTTP `Request`, and FastAPI does not resolve `Request`-typed dependencies for a `@router.websocket(...)` route (confirmed live — it raises a "missing required positional argument" `TypeError` at connection time, not a clean 4xx). `routes/ws.py` reads `websocket.app.state.*` directly instead.
- `connection_manager.py`: `ConnectionManager` — a `set[WebSocket]` registry with `register`/`unregister`/`broadcast(message)`, where `broadcast` iterates a snapshot and drops (logs, doesn't raise) any connection whose `send_json` fails, so one dead client can never block delivery to the others. `__main__.py` wires the real provider map, the real `Scheduler`, and the real `ConnectionManager` in; tests that don't need `/api/providers`, `/api/sync-now`, or `/api/ws` simply omit them.
- `routes/audit.py` (`GET /api/audit-events?event_type=&account_key=&include_skipped=&sort_by=&sort_dir=&limit=&offset=` — the first query-param GET route in this codebase, every prior one took no arguments; thin wrapper over `db.list_audit_events()`/`db.count_audit_events_by_type()`, returning `{events, total, counts}`; `sort_by`/`sort_dir` are `Literal` types matching `StateDB.AUDIT_EVENT_SORT_COLUMNS`, so FastAPI itself rejects an unsortable column with a 422 before `list_audit_events()`'s own allowlist check is ever reached — belt and suspenders, not redundant, since the DB layer must stay safe even if a future caller bypasses this route; FastAPI's own `Literal`/`Query(ge=...)` validation handles all other bad input with a 422 too, no custom error handling needed since this is a pure read endpoint).
- `routes/status.py` (`GET /api/status`, mirrors `db.read_run_metadata()` directly rather than a second MQTT subscription; its `accounts` list is now sourced from `db.list_mappings()` rather than `config.accounts` — same response shape/keys the frontend already expects, `ynab_budget` is mapped back from the mapping's stored budget id to the human-readable config alias — the dashboard renders this field directly and a raw UUID there would be a visible regression — plus new `provider`/`enabled` fields; `next_fire_at` is computed via `cron.next_fire_at(config.sync.cron_expression, config.sync.timezone)`, not inline UTC math — see the root CLAUDE.md's "Resolved: cron ran in UTC, not local time").
- `routes/deleted.py` (`GET /api/deleted-transactions`, `POST /api/deleted-transactions/{tracking_key}/readd` — thin wrappers over already-tested `StateDB`/`SyncEngine` methods).
- `routes/file_import.py` (`POST /api/import` — the convergence point: always re-parses the uploaded file from scratch on every call, dry-run or not, so the frontend's preview→confirm flow needs no server-side session; resolves the target account via explicit override against any DB mapping → else exactly one *enabled* mapping's `import_source_name` → else rejects with `import_messages.py`'s deliberately sarcastic copy; its `summary` dict key is `"errors"` (plural, fixed from a real bug), matching `frontend/src/api/client.ts`'s `ImportSummary`; a YNAB-side failure during the commit (`httpx.HTTPStatusError`/`TransportError` from `engine.import_file_rows()`) is caught and reported as a 503 with another `import_messages.py` copy pool (`ynab_unavailable()`) — deliberately **no retry/backoff here**, unlike the scheduled path, since this is a single user-initiated request with no background loop to retry it in).
- `routes/mappings.py` (`GET/POST/PATCH/DELETE /api/mappings` — CRUD over `StateDB`'s `account_mappings` table for the drag-drop mapping UI; every list/create/update response is enriched with `tracked_count` via `db.count_tracked_for_account` so the UI can warn before a remap; `MappingValidationError` → 422, unknown id → 404, and `ynab_budget_id` is validated against `config.ynab.budgets.values()` on every create/update since that's no longer a startup-time guarantee now that mappings are mutable; also `DELETE /api/mappings` with no id — a distinct, literal path from `DELETE /api/mappings/{mapping_id}` — bulk-deletes every mapping via `db.delete_all_mappings()` and returns `{"deleted": n}`, the Mappings tab's "Clear all" button).
- `routes/providers.py` (`GET /api/providers?force_refresh=` — per configured provider, its `list_accounts(force_refresh=force_refresh)` result flagged `mapped: bool` against current DB mappings; `force_refresh` is a plain passthrough — a provider that caches internally (SpareBank1) uses it to bypass that cache, one that doesn't just ignores it; a provider raising `ProviderAuthRequiredError` reports `auth_required: true` with an empty account list instead of failing the whole response, and any other exception is caught and reported as an `error` string on that provider's own entry — one broken provider must never 500 the page for every other provider's accounts; `GET /api/ynab/accounts?force_refresh=` — every configured budget's accounts, the drop targets, served through `YnabAccountsCache` (see `ynab/client.py`) the same way `/api/providers` serves through each provider's own cache — `force_refresh` bypasses it identically).
- `routes/sync_now.py` (`POST /api/sync-now` — calls `scheduler.request_sync_now()`; 503 with a clear message if no scheduler was wired into this app instance).
- `routes/pause.py` (`POST /api/pause`, body `{"paused": bool}` — calls `scheduler.set_paused()`, same optional-scheduler-503 guard as `sync_now.py`; see root CLAUDE.md's "GUI pause toggle").
- `routes/settings.py` (`GET/PATCH /api/settings` — currently just `log_level`; `GET` returns `db.read_run_metadata()["log_level"]` or, if that's `NULL`, `config.logging.level` — see root CLAUDE.md's "Runtime-configurable log level"; `PATCH` persists via `db.set_log_level()` AND calls `logging_setup.configure_logging()` again immediately, so the change takes effect on the running process with no restart, not just on the next one).
- `routes/ws.py` (`GET /api/ws` — the GUI's live push-update channel, see root CLAUDE.md's "Live GUI push updates"; refuses the connection with close code 1011 rather than crashing when `app.state.ws_manager` is `None`).
- No application-level auth (see root CLAUDE.md's non-goals) — `deploy/swag/ynab.subdomain.conf` is a sample reverse-proxy config for fronting it with SWAG + something like Cloudflare Access; that file also now documents the `Upgrade`/`Connection` headers a websocket route needs from the proxy, which a plain HTTP-only reverse-proxy config would otherwise silently omit.
